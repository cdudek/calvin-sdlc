Colour world 1 — Web & Product

Semantic UI tokens. Valid exclusively for websites, web apps, dashboards, website and app mockups, design handoffs, component specs and anything that ends in code. Never carry them into slides, PDFs, ad assets or charts. The token rule applies here: write the token in code, never the hex value. The hex column serves only for checking and for handing over to tools without token resolution.

The complete sets are in the cards of this section: Background colors, Brand palette, Surface & elevation, Text colours, Status colours, Neutral scale.

Do

  • In code set semantic tokens only, never raw hex values or --color-* primitives.
  • One brand accent per view. The normal case is the selected state from bg-primary-subtle.
  • Depth via surface tiers and hairline frames, not via shadows.
  • Hover and press via state-layer overlays, never via a hard-set grey surface.

Don't

  • No #8259ff, #00adad, #f2b200 or any other brand-kit value in product UI.
  • No graphic tokens (--graphic-color-*) for UI surfaces, text or frames. Those are colour world 2.
  • Never use status colours decoratively. They communicate a state.
  • No gradients unless the user explicitly asks for them.

The only bridge between the colour worlds

Only these two tones may be carried from the UI colour world into editorial and ad assets. Exclusively as box and surface backgrounds: callouts, cards, table rows, quote boxes. Not for text, icons, lines, chart series or full-bleed backgrounds. No further UI token follows this exception.
